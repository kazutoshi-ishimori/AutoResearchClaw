## 2. 研究目的・方法など

### 2.1 本研究の学術的背景と核心的「問い」

大規模言語モデル（LLM）を中核とする自律研究エージェント——文献探索・仮説生成・実験コード生成・結果解釈・論文執筆を連結し実行するパイプライン——は、2024〜2026 年にかけて急速に実用段階へ移行した。汎用系では AI Scientist（Sakana AI, 2024）、AutoResearchClaw（aiming-lab, 2026）、A-Evolve（2025）が、生物医学特化系では Biomni（Stanford, 2025、CRISPR・single-cell RNA-seq・ADMET・GWAS・希少疾患診断等を網羅する汎用 biomedical AI agent）、STELLA（self-evolving biomedical agent, 2025、Manager / Developer / Critic / Tool Creation Agent からなるマルチエージェント構成で能力を自己進化させる設計）が登場し、「研究プロセスそのものの自動化」は研究方法論上の新たな独立したパラダイムとなりつつある。

しかし、**これら能力型エージェントはいずれも外部クラウド API（OpenAI, Anthropic, Google 等）への依存・PubMed や GitHub 等の外部基盤への動的アクセス・実行時のネットワーク／システムコマンド権限**を前提として設計されており、個人情報保護法・改正個人情報保護法・各種データ利用規程の下で**機微な実験データには一切適用できない**という構造的制約を抱えている。事実、Biomni 自身が「本番利用時は隔離環境推奨」「生成コードがファイル・ネットワーク・システムコマンドへアクセス可能」と注意喚起しており、STELLA も外部基盤モデル・動的ツール作成を前提としている——いずれも閉域・監査・機微データ運用は主題としていない。特に全ゲノム解析データや大規模コホートの臨床情報、希少サンプルに由来する一次測定値は、それ自体が個人や試料を再識別しうる情報として扱われ、**共同利用・共同研究拠点**をはじめとする国内外の大規模実験データ集積基盤は、分譲先の閉域解析環境からのデータ持ち出しを厳格に禁じている。結果として、**急速に成熟している能力型エージェント技術が、その恩恵を最も必要とする大規模実験データに届かない**という深刻な技術的・社会的ギャップが存在している。

本研究の核心的な学術的問いは以下である：

> **「Biomni、STELLA、AutoResearchClaw 等の能力型自律研究エージェント技術を、外部通信ゼロ・個人情報残留ゼロの閉域環境下で安全・再現可能・監査可能に運用するために、いかなる要件・アーキテクチャ・評価方法論が必要か」**

この問いは、能力型エージェントの SOTA を競うものではなく、**既に成熟しつつある能力型エージェント技術を「日本の医学系閉域データ環境で本当に使えるのか」というメタな運用研究の問い**である。AI 駆動型研究の適用可能範囲を「公開データ領域」から「機微実験データ領域」へと拡張するための方法論的基盤を問うものであり、AI for Science 分野における未踏の課題である。

### 2.2 本研究の目的と学術的独自性・創造性

本研究の目的は次の三点である。**いずれも能力型エージェント研究（Biomni、STELLA、AutoResearchClaw 等）の能力 SOTA を競うものではなく、それらを閉域条件で運用するためのメタ研究としての位置づけである。**

**目的 1（閉域化要件の定義）**
能力型自律研究エージェントが一般に依存する外部リソース——外部 LLM API、文献検索 API（PubMed 等）、外部基盤モデル、コード実行時のネットワーク／システムコマンド権限、動的ツール作成、外部ログ／キャッシュ——を**系統的に列挙**し、それぞれを閉域環境で代替するために必要な要件を整理する。本研究では `AutoResearchClaw` v0.4.0 を主たる検証基盤として、Biomni / STELLA 等にも一般化可能な閉域化要件をフレームワーク化する。

**目的 2（安全運用アーキテクチャの最小実装）**
通信遮断（`offline_mode` + `nftables` レベルでの恒常検証）、PHI マスキング（多層防御による Recall ≥ 0.95）、hash chain 監査ログ、HITL（Human-in-the-Loop）ゲート、再現性評価基盤を備えた**閉域運用最小パイプライン**を構築する。Apache 2.0 ライセンスの OSS `AutoResearchClaw` v0.4.0 を主実装基盤とし、ローカル LLM（Qwen 3.5、Gemma 4 等）、ローカル埋め込みモデル、ローカル文献コーパス（小規模版）による全置換を行う。**本研究の目標は「自律研究エージェントを新規開発すること」ではなく、「既存の能力型エージェントを閉域条件で安全に動かすための運用基盤を最小実装として示すこと」**である。

**目的 3（既存エージェント型手法との差分評価）**
クラウド型・オンライン型エージェント（特に Biomni、STELLA、AutoResearchClaw 原版）と比較し、閉域化による**性能低下・安全性向上・再現性・研究者介入量の差分**を 6 軸の運用方法論評価フレームワークで定量化する。あわせて、**共同利用・共同研究拠点**の閉域解析環境への接続要件（規程・ネットワーク・GPU・運用 SLA）を整理し、本研究期間後の機微実験データへの適用に向けた**接続仕様書**を整える。これにより、能力型エージェント技術を機微実験データ環境で運用する際の方法論を学術的に確立する第一歩とする。

**学術的独自性・創造性**：

本研究は、Biomni、STELLA、AutoResearchClaw 等の能力型エージェント研究の SOTA を競うものではなく、それらの能力型エージェントを**機微実験データを含む閉域研究環境で安全・再現可能・監査可能に運用するためのメタ研究**として位置づけられる。具体的には次の三点に独自性がある。

- **第一**に、能力型エージェント研究の代表（Biomni、STELLA、AutoResearchClaw 等）を**横断的に俯瞰し、それらに共通する閉域化要件**を抽出する初の体系的試みである。能力競争ではなく**「能力型エージェントを閉域でどう動かすか」という運用研究の独立トラック**を切り拓く。
- **第二**に、LLM を含む研究プロセス全体に対して**外部通信ゼロを設計原理として保証**するアプローチは、既存の "差分プライバシー"・"連合学習" 等の部分的プライバシー保全手法とは本質的に異なる、新規の運用設計である。能力型エージェントは Biomni / STELLA を含めいずれも**「本番利用時は隔離環境推奨」程度の注意喚起にとどまっており、隔離環境そのものをどう構築・検証するかの体系的研究は未確立**である。
- **第三**に、監査可能性と説明責任を備えた AI 駆動研究基盤は、研究公正（Research Integrity）と AI 倫理の接点における新たな学術的知見を提供し、機微実験データを扱う共同利用・共同研究拠点等の運用に直接寄与する。

### 2.3 本研究で何をどこまで明らかにするか

本研究は **6 ヶ月**で以下を達成する。**機微実験データの実証実験そのものは本研究では実施せず**、本研究はその前段となる「閉域動作の方法論的妥当性確認」「保全機構の動作検証」「拠点接続要件の整理」までを射程とする。

| 段階 | 達成目標 | 評価方法 |
|---|---|---|
| 基盤実装 | 外向き通信ゼロを `nftables` レベルで検証可能な閉域パイプラインの最小実装 | 計測値 0 を CI で確認 |
| PHI 保全機構 | マスカー実装＋小規模アノテート評価セットでの定量評価（**Recall ≥ 0.95** を主目標、F1 ≥ 0.80 を補助） | 評価セット 200〜500 件で算出 |
| 文献基盤 | 学外 DMZ 構築コーパス（**≥3,000 論文**・PubMed OA サブセット）のローカル検索基盤 | 検索 Recall@10 ≥ 0.6 |
| 動作実証 | 公開データ（1000 Genomes 等）で end-to-end 論文生成 1 本を完遂 | 23 ステージ中 ≥ 16 ステージ完走（≥ 0.70） |
| 接続要件整理 | 共同利用・共同研究拠点での運用に必要な規程・GPU・ネットワーク要件の文書化 | 接続仕様書 v1 として成果物化 |
| 方法論 | 閉域自律研究パイプラインの設計原則と評価フレームワークをまとめた**方法論論文の投稿可能原稿**を完成 | 共著者レビュー可能な完成稿（投稿はストレッチ） |

> **PHI マスカー評価指標の用語解説**
>
> 表中の Recall・F1 は、機械学習の分類問題で標準的に用いられる評価指標である。本研究の文脈で噛み砕くと次の通り。
>
> - **Recall（再現率／検出率）**：本来 PHI として除去されるべきトークンのうち、マスカーが実際に除去できた割合。
>   `Recall = 正しく検出した PHI 件数 ÷ 評価セットに含まれる全 PHI 件数`。
>   1.0 に近いほど「**漏らしていない**」。
> - **Precision（適合率）**：マスカーが PHI と判定したもののうち、実際に PHI だった割合。
>   `Precision = 正しく検出した PHI 件数 ÷ マスカーが PHI と判定した全件数`。
>   1.0 に近いほど「**誤検出していない**」（PHI でない一般語を消し過ぎていない）。
> - **F1**：Recall と Precision の調和平均で、両者のバランスを示す総合指標。
>   `F1 = 2 × Precision × Recall ÷ (Precision + Recall)`。
>
> 機微実験データの保全という目的上、**「PHI が漏れる（Recall が低い）」ことの被害は、「PHI でない語を消し過ぎる（Precision が低い）」ことの被害より圧倒的に大きい**——前者は外部流出という不可逆な事故、後者は文章の冗長化という運用負荷に過ぎない。本研究では Recall を 0.95 以上に固定し、Precision は許容可能な範囲（F1 ≥ 0.80 が成立する程度）にとどめる方針をとる。すなわち**「漏らさない方向」に意図的に倒した運用設計**である。

### 2.4 着想に至った経緯と国内外研究動向

**着想の経緯**：
本研究グループの実装担当（研究協力者 4：システム設計・実装）は、AI を中核に据えたソフトウェア開発に 1 年以上の実務経験を有する。Apache 2.0 公開された自律研究エージェント `AutoResearchClaw`（初版 2026 年 3 月公開、v0.4.0 が 2026 年 4 月時点最新）が登場した直後より、公開データ領域での論文生成タスクに対し本パイプラインを実運用し、その有用性と限界を実地で検証してきた（v0.4.0 への upstream 貢献として S2 rate limit 修正等の実績を有する）。この過程で、「**共同利用・共同研究拠点**等の機微実験データに同様の方法論を適用できないか」という実務課題に直面し、既存システムがクラウド前提であるがゆえに本質的に適用不可能であることを確認した。この構造的課題を克服する新たな研究基盤の構築こそ、日本の研究 DX にとって最優先の課題であるとの認識に至り、本研究では**まず半年でその「方法論的足場」を作り切る**ことを目指す。

**国内外研究動向**：

| 研究 | 主眼 | 弱点・未解決点 |
|---|---|---|
| Biomni（Stanford, 2025） | 生物医学タスクを広く実行する汎用エージェント。CRISPR、single-cell RNA-seq、ADMET、GWAS、希少疾患診断等のタスクをカバー。データレイク・ツール群・評価ベンチマーク提供。Claude / OpenAI / Gemini / Bedrock / Groq / Custom / Ollama 系の設定を持ち、ローカル LLM 方向にも進展 | 本番利用時は隔離環境推奨。生成コードがファイル・ネットワーク・システムコマンドへアクセス可能との注意喚起あり。閉域・監査・機微データ運用は主題ではない |
| STELLA（self-evolving biomedical agent, 2025） | 自己進化する生物医学エージェント。Manager / Developer / Critic / Tool Creation Agent からなるマルチエージェント構成。Template Library と Tool Ocean を更新しながら能力を拡張 | PubMed / GitHub 検索や外部基盤モデル・動的ツール作成を前提とし、閉域・監査・機微データ運用が主題ではない |

- **能力型エージェント研究の成熟**：上記の通り、Biomni・STELLA に代表される生物医学特化エージェント、AI Scientist・AutoResearchClaw に代表される汎用エージェントが**ともに能力面で実用段階に到達**しつつある。
- **ローカル LLM**：Qwen 3.5（Alibaba, 2026）、Gemma 4（Google, 2026）の登場により、Apache 2.0 ライセンスかつ閉域運用可能な大規模モデルが初めて現実的な選択肢となった。
- **機微実験データと AI**：連合学習・差分プライバシーが主流だが、これらは統計モデリングに閉じており、**研究プロセス全体の自動化には適用できない**。
- **本研究の位置づけ**：能力型エージェント研究が成熟したからこそ問える「**では、これらを日本の医学系閉域データ環境で本当に使えるのか？**」という運用方法論の問いに正面から取り組む。これは能力 SOTA 競争とは独立した、**運用研究の新領域**である。Biomni / STELLA / AutoResearchClaw 等の能力型エージェント研究の進展は、本研究の追い風となる（閉域化対象の選択肢が広がるため）。

## 3. 研究方法

### 3.1 全体設計（6 ヶ月計画）

既存 OSS `AutoResearchClaw` v0.4.0 を**主たる実装基盤**に、**6 フェーズで半年に圧縮**する。詳細は `requirements.md`（別紙）を参照。v1 にあった「ドメイン特化スキル拡張」「実データ実証」「複数論文化」は、本研究の射程外（次年度以降の本格展開に位置づけ）。

> **Biomni / STELLA の位置づけ**：本研究期間内では、Biomni / STELLA は**比較対象（ベースライン）**として位置づけ、ARC で先行する閉域化要件・運用評価フレームワークが**能力型エージェント一般に通用するか**を検証するための材料として用いる。Biomni / STELLA 自身の閉域改修（ローカル LLM への全置換、外部基盤模倣、PHI 保全機構の組込み等）は、本研究で確立する**閉域化要件フレームワークを次年度以降に Biomni / STELLA へ展開する形**で位置づける。半年スコープでは ARC を主基盤とし、Biomni / STELLA は公開データでの動作確認とクラウド型ベースラインとしての対比測定にとどめる。

| フェーズ | 内容 | 期間 | 主要成果物 |
|---|---|---|---|
| Phase 0 | 要件確定・規程確認・GPU 調達／環境調査 | 0.5 ヶ月 | 接続要件ドラフト、開発環境 |
| Phase 1 | `offline_mode` フラグ＋外部通信遮断機構（`nftables` 計測込み） | 0.5 ヶ月 | 通信ゼロ動作 CI |
| Phase 2 | ローカル LLM バックエンド統合（Qwen 3.5 / Gemma 4） | 1.0 ヶ月 | LLM 推論サーバ |
| Phase 3 | ローカル埋め込み・ベクタ検索＋小規模文献コーパス（≥3,000 論文） | 1.0 ヶ月 | 文献検索基盤 v1 |
| Phase 4 | PHI マスカー＋HITL ゲート＋hash chain 監査ログ | 1.0 ヶ月 | 保全機構 v1、評価セット |
| Phase 5 | 公開データでの E2E 動作実証＋ 6 軸評価＋方法論論文の最終仕上げ（投稿可能原稿化） | 2.0 ヶ月 | E2E ログ、評価表、方法論論文の**投稿可能原稿** |

> **論文の並行執筆**：方法論論文の Introduction / Methods / System Design は、評価データを待たずに **M1〜M3 から並行執筆を開始**する。M5 の評価結果は Results にそのまま貼り込める形式（図表テンプレート・表セル定義）で取得し、M6 後半で全体を投稿可能原稿として仕上げる。

> **半年で削ったもの／割り切り**
> - 共同利用・共同研究拠点の実データを用いた論文生成は**実施しない**。本研究では公開データで E2E 動作までを示し、機微実験データへの適用は接続仕様書の整備までとする。
> - 文献コーパス規模は 10 万論文ではなく **3,000 論文程度**（PubMed OA サブセット中心、検索動作確認に必要十分な最小規模）に縮小。
> - PHI マスカー目標は **Recall ≥ 0.95（漏れの最小化を最優先）／F1 ≥ 0.80** に再設定。Precision より Recall を優先することで、半年で到達可能かつ「漏らさない」運用に倒す。
> - 自動化完遂率は 23 ステージ全完遂ではなく **≥ 0.70（公開データ 1 テーマ）**。半年では「最低 1 テーマでの動作実証」を必達ラインにする。
> - 評価フレームワーク論文は本研究期間内に投稿を目指すが、Accept は次年度に持ち越し可とする。
> - ドメイン特化スキル（WGS・拠点特有コホート対応）は本研究期間外。

### 3.2 評価設計（自動化性能の定量評価）

類型 5（実験自動化・自律化）に対応する本研究では、**自動化そのものの性能**を以下の 6 軸で定量的に評価する。半年版では各目標値を「**到達可能ベースライン**」として再設定する。

| 評価軸 | 指標 | 目標値（v2 半年版） |
|---|---|---|
| **自動化完遂率** | ステージ単位の完遂率（全 23 ステージ中の達成数 / 総数、公開データ 1 テーマ） | ≥ 0.70 |
| **研究者工数削減率** | 自動生成 vs 人手執筆の工数比（公開データ 1 テーマで計測、計測方法論の確立を優先） | 参考値を提示／削減傾向の確認 |
| **セキュリティ** | 外向き通信回数（nftables 計測） | 0 |
| **PHI 保全** | マスカー Recall / F1（小規模アノテート評価セット 200〜500 件） | **Recall ≥ 0.95** ／ F1 ≥ 0.80 |
| **再現性** | 同一入力・同一シードでの出力類似度（BERTScore 等、3 ラン平均） | ≥ 0.70 |
| **成果物品質** | 分野専門家によるルーブリック評価（5 段階 × 6 軸、レビュア 2 名以上） | 中央値 ≥ 3.0 |

この 6 軸評価は、**自律研究システムに対する評価フレームワーク**そのものを方法論論文として打ち出す材料ともなる。

### 3.3 ベースラインとの比較

以下 4 条件で比較実験を行い、**本システムの能力的優位性ではなく**、「閉域条件下での性能低下／安全性向上／再現性／介入量」の差分を 6 軸評価フレームワークで定量化する。半年計画では**公開データ 1 テーマ**でこの差分計測を完結させる。

- **ベースライン A**：完全人手による従来の研究プロセス（過去ログから工数推定）
- **ベースライン B**：クラウド LLM 利用可能な公開データでの **AutoResearchClaw 原版**（外部通信あり、能力フル）
- **ベースライン C**：参考対比対象として **Biomni** および **STELLA**（公開データでの動作確認、原版のままクラウド型として運用）
- **本システム**：閉域・ローカル LLM 版 AutoResearchClaw

> **Biomni / STELLA の取り扱いに関する注**：本研究期間内では Biomni / STELLA については**閉域化を施さず**、公開データで一般動作を確認したうえで、ベースライン B（ARC 原版）と本システムとの差分が**能力型エージェント間で一般化するか**を間接的に検証する。半年スコープでは Biomni / STELLA 自身の閉域改修は実施せず、原版動作の確認と運用要件マッピング（外部依存の列挙、本研究の閉域化要件フレームワークへの照合）にとどめる。

## 9. リスクと対応方針（半年版）

| リスク | 影響 | 対応 |
|---|---|---|
| 規程上 LLM 利用不可 | プロジェクト成立不可 | **Phase 0（M1 前半）で規程確認を最優先**。利用不可の場合は公開模擬データに切替し、方法論検証に絞り込む計画 B を維持 |
| ローカル LLM 品質不足 | E2E 完走不可 | Qwen 3.5 / Gemma 4 を比較選定。半年では「最低 1 モデルで 23 ステージ中 ≥ 16 ステージ完走」を目標とし、全ステージ完走と品質最適化は次年度 |
| 倫理審査長期化 | 公開データ実証への影響は小、将来運用への影響は大 | IRB 申請は**準備のみ Phase 0 と並行**、本研究期間内の実証は公開データに限定 |
| Upstream との衝突 | 保守負荷増 | アダプタ／プラグイン形式で実装し、本体ファイル改変を最小化 |
| PHI マスカー漏れ | 重大インシデント（次年度実データ運用時） | 正規表現＋語彙＋単体テスト＋ランダムサンプル人手レビューの多層防御。半年版は評価セット 200〜500 件で **Recall ≥ 0.95** を担保（漏らさない方向に倒す） |
| 研究期間 6 ヶ月という制約自体 | 当初目標の取りこぼし | **「方法論的妥当性検証」「接続仕様書」「方法論論文の投稿可能原稿」を必達ライン**、査読誌投稿・国内学会発表・評価精度向上はストレッチ目標として明示分離 |
| 評価データの遅れによる論文化の連鎖遅延 | 投稿可能原稿の完成不可 | 論文の Introduction / Related Work / System Design / Methods / 評価設計章を **M1〜M4 で並行執筆**、評価結果は Results 章のテンプレートに直接転記する形式で取得し、M6 後半は Discussion / Limitations と仕上げに集中 |

> **PHI マスカー多層防御の構成（4 層 defense-in-depth）**
>
> 単一の検出機構では Recall ≥ 0.95 を信頼性をもって担保できないため、**4 層の独立した検出・抑止層を直列に配置**する。前段が漏らしても後段が捕捉する構造により、運用時の Recall を維持し続ける。
>
> 1. **正規表現層（パターンマッチ）**：氏名候補、電話番号、メールアドレス、郵便番号、住所構成要素、生年月日（西暦・和暦・スラッシュ／ハイフン区切り等の多形態）、保険証番号、検体 ID、患者 ID、施設 ID 等の**機械的に判定可能なパターン**を網羅。日本語・英数字双方の表記揺れに対応。
> 2. **語彙層（辞書照合）**：日本人姓名辞書（≥ 5 万エントリ）、医療施設名・病院名辞書、地名辞書、希少疾患名辞書等の**ドメイン辞書**を完全一致・部分一致で参照。正規表現で拾えない「文字列としては一般的だが文脈上 PHI となる語」（例：希少な姓、特定施設の通称）を検出する。
> 3. **単体テスト層（CI 回帰検出）**：上記 1・2 を**評価セット 200〜500 件**に対して常時回し、CI で回帰検出する。Recall が 0.95 を割った時点でビルドを失敗させ、本体へのマージを物理的に阻止する。
> 4. **ランダムサンプル人手レビュー層**：マスカー処理後の出力からランダムに 5% 程度を抽出し、共同研究者または RA が**人手で漏れの有無を確認**する。発見された漏れは即座に正規表現層／語彙層に反映するフィードバックループを運用。
>
> **「漏れた場合の取り返しのつかなさ」を考慮し、Precision の低下（過検出）は許容しつつ Recall を最優先する設計**である（過検出は人手レビューで戻せるが、漏れは外部流出という不可逆事故になり得るため）。
